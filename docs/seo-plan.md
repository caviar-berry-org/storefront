# SEO, AI-видимість і UTM — аудит і план

Складено 13.11.2026 на основі аудиту кодової бази та згенерованого HTML, а не припущень.
Етап 3 дорожньої карти. Нічого з цього ще не реалізовано.

## 1. Що виміряно

Аудит проведено по згенерованих файлах `.next/server/app/*.html` після `npx next build --webpack`.

### Працює вже зараз

| Факт                                                                     | Де перевірено                                   |
| ------------------------------------------------------------------------ | ----------------------------------------------- |
| Вітрина — **SSG**: `/ua`, `/en`, 8 товарів × 2 локалі прередерені        | вивід білду (`●`)                               |
| `metadataBase`, `canonical`, `hreflang` (`uk`/`en`/`x-default`) без UTM  | `src/lib/metadata.ts`                           |
| `robots`: поза продом усе `disallow`, плюс `X-Robots-Tag` у заголовках   | `src/app/robots.ts`, `next.config.ts`           |
| `/admin` і `/api` закриті від індексації                                 | `src/app/robots.ts`                             |
| SEO товару (заголовок, опис, зображення, двомовно) редагується в адмінці | `caviar-editor.tsx`, `caviar-form.ts`           |
| `/privacy`, `/terms` → 308 на `/offer`                                   | `privacy/page.tsx`                              |
| Сторінка статусу замовлення — `noindex`, `no-referrer`                   | `order/[orderId]/page.tsx`                      |
| Ціни, ваги й назви товарів **є у серверному HTML**                       | `grep` по `.next/server/app/ua/products/*.html` |
| Усі 8 абзаців FAQ **є у серверному HTML**                                | звірка `faq.paragraph*` з `ua.html` — 8 із 8    |

Останні два пункти важливі: вони означають, що базова умова AI-видимості виконана — факти
лежать у тексті, а не тільки в JS.

### Прогалини, за пріоритетом впливу

Нумерація — порядок впливу на момент аудиту. **Усі вісім закриті**; вимірювання «до» лишаю,
бо це єдиний спосіб побачити, чого саме коштувала кожна прогалина.

1. **Нуль структурованих даних.** `grep "ld+json"` по всьому `src/` і по згенерованому HTML — 0 збігів.
   Немає `Product`/`Offer`, `Organization`, `WebSite`, `BreadcrumbList`, `FAQPage`.
   Google не може показати ціну й наявність у результатах — це найбільша втрата.
   → **Закрито в S2.** Зараз у HTML один граф на сторінку: головна — `Organization`, `WebSite`,
   `FAQPage`, `ItemList`; товар — `Product` з `AggregateOffer` і `BreadcrumbList`.
2. **Три статті не існують для пошуку.** Звірка `article-*` ключів із `ua.html`: **0 із 13**.
   `article-reader.tsx` рендериться лише в оверлеї (`if (!overlay) return null`), а картка в блозі —
   це `<button action="post">` без `href`. Готовий редакційний контент, який нічого не коштує відкрити.
   → **Закрито в S3.** `0 із 13` стало `4 із 4` на перевіреній статті; картка — справжнє посилання.
3. **Подарункові набори не мають ні URL, ні місця в `sitemap.ts`.** Комерційний розділ невидимий.
   → **Закрито в S2/S3** без окремих сторінок: `ItemList` на головній і якір у карті сайту.
   `Offer` у наборів немає навмисно — вони створюють заявку, а не покупку.
4. **`sitemap.ts` мінімальний:** головна + товари ікри. Немає `lastModified`, `alternates.languages`,
   `images`, немає `/offer`. Без `lastModified` краулер не знає, коли перечитати сторінку.
   → **Закрито в S3.** Дати, мовні пари, зображення, оферта й журнал; виключення приховних і
   `checkout-test` під тестом.
5. **OG-прев'ю неоптимальне:** `serve-premium.jpg` 1400×933 (аспект 1.5 замість 1.91), без
   `width`/`height` у метаданих, однакове для всіх сторінок окрім товарів.
   `openGraph.locale: "en"` — невалідне значення, має бути `en_GB`.
   → **Закрито в S1.** Прев'ю 1200×630 на локаль статичним файлом, розміри в метаданих, локаль
   виправлена. Побіжно: явні `icons` у лейауті перебивали файлову конвенцію, тож
   `apple-touch-icon` вказував на 600×457.
6. **Немає явних правил для AI-краулерів** і немає `llms.txt`.
   → **Закрито в S4.** Окремі групи для ботів, що цитують, і тренувальних; `llms.txt` генерується
   з живого каталогу. Плюс e2e-тест на видимий текст — головний захист, а не самі файли.
7. **Немає UTM і жодної аналітики.** `PageVisit` лише пише останній шлях у `sessionStorage`.
   Дашборд має чотири незаповнені заготовки: «Відвідування», «Переходи за UTM», «Регіони», «Країни».
   → **Закрито в S5 частково:** «Переходи за UTM» працює на власних даних, нуль додаткових записів.
   «Відвідування», «Регіони», «Країни» лишаються за GA4 — див. рішення 2.
8. Дрібне: немає `manifest`, `apple-icon`, файлових конвенцій `opengraph-image`/`twitter-image`.
   → **Закрито в S1.** `manifest.ts` і `apple-icon.png` 180×180. Файлові конвенції `opengraph-image`
   свідомо не використані: прев'ю задається через `pageMetadata`, бо товарні сторінки мають власне
   зображення, і дві системи на одне й те саме плутали б.

## 2. Головний висновок ресьорчу

Експеримент 2025 року (SearchVIU) показав, що ChatGPT, Claude, Perplexity і Gemini **не побачили**
дані товару, які існували **тільки** в JSON-LD.

Практичний висновок, який визначає весь план:

- **JSON-LD — для Google rich results**, а не для AI. Робимо його повно й правильно, але не вважаємо
  достатнім.
- **Для AI-видимості факти мусять бути у видимому тексті HTML.** Тут ми вже в доброму стані (ціни,
  ваги, FAQ у HTML), і саме цей інваріант треба захистити тестом, а не лише разовою перевіркою.
- `llms.txt` — неформальна конвенція без стандарту. Claude і Perplexity її читають, Google ігнорує.
  Дешево зробити, помірний виграш; генеруємо з того ж джерела, що каталог, щоб не застаріла.

## 3. Етапи

**Статус: S1–S6 виконані 13.11.2026.** Реєстрація в Search Console і Bing Webmaster — окремий
наступний етап (кроки 32+ у `docs/release-checklist.md`). Опис кожного етапу лишаю як запис про
причину рішень; нижче кожен має позначку, що саме зроблено.

### S1 — Прев'ю посилання й гігієна метаданих

**Зроблено:** `scripts/build-social-preview.ts` (`npm run social:build`) робить 1200×630 на локаль із майстра один раз, статичним файлом — нуль трансформацій. Додано `apple-icon.png` 180×180 і `manifest.ts`. `openGraph.locale` виправлено на `uk_UA`/`en_GB` плюс `alternateLocale`; розміри оголошуються **лише** для нашого прев'ю — у фото товару розмір невідомий, а хибна ширина гірша за відсутню.

- `opengraph-image` 1200×630 на локаль, **статичним файлом** (не через `next/image`, за правилами
  медіа-піпелайну), плюс `apple-icon` і `manifest.ts`.
- `openGraph.locale` → `uk_UA` / `en_GB`; `width`/`height`/`type` у масиві `images`.
- **Модерація в адмінці:** заголовок і опис головної сторінки на локаль — так (клієнт просив
  мінімальну модерацію, і це рівно ті два рядки, які він захоче правити).
  Картинка прев'ю — ні: один статичний файл, який має бути закодований заздалегідь; завантаження
  через адмінку тягне Cloudinary туди, де він не потрібен. До релізу міняємо вручну.

### S2 — Структуровані дані

**Зроблено:** `src/domain/structured-data.ts` — чисті білдери без React, Next і бази. На головній: `Organization`, `WebSite`, `FAQPage` (із тих самих 8 пар, що вже видимі в HTML), `ItemList` наборів **без** `Offer` — набір не купується, а створює заявку. На товарі: `Product` з `AggregateOffer` (ціна з мінорних одиниць точно, наявність із `sellableQuantity`, вага в `GRM`) і `BreadcrumbList` із мітками видимої навігації. `hasMerchantReturnPolicy` = `MerchantReturnNotPermitted` — це пряме відображення §9.1 оферти, а не вигадка. `shippingDetails` **свідомо відсутній**: перевізника оплачує одержувач, тариф ми не беремо. Опис товару екранується, тож `</script>` у каталозі не може закрити тег — під тестом.

Чисті білдери в `src/domain/structured-data.ts` (без React, Next і Firestore) + серверний `<JsonLd>`.

- `Organization` + `WebSite` у лейауті локалі (`logo`, `sameAs` із `src/content/contacts.ts`, `contactPoint`).
- `Product` + `Offer` на сторінці товару: один `Offer` на фасування, `priceCurrency: UAH`,
  `availability` з `sellableQuantity`, `weight`, `brand`, `image`, `shippingDetails`,
  `hasMerchantReturnPolicy` (Google вимагає обидва для торгового rich result).
- `FAQPage` на головній із наявних пар `faq.text*`/`faq.paragraph*` — текст уже видимий, тобто
  вимогу Google «розмітка відповідає видимому контенту» виконано.
- `BreadcrumbList` на сторінці товару.
- `Product` без `Offer` для подарункових наборів (вони не купуються напряму, а створюють заявку —
  `Offer` там був би неправдою).
- **Виключення:** приховані, архівовані й `checkout-test` ніколи не потрапляють у розмітку.
  Закріпити тестом, а не оглядом.

### S3 — Індексована площа контенту

**Зроблено:** `/[locale]/journal/[slug]` — три SSG-сторінки на локаль. Було `0 із 13` абзаців у HTML, стало `4 із 4` на перевіреній статті. Три компоненти `Article0/1/2` замінені однією таблицею блоків (`src/content/journal.ts`) і одним рендерером, яким користуються і оверлей, і сторінка — DOM у читалці не змінився. `Action` отримав необов'язковий `href`: картка блогу тепер справжнє посилання, а звичайний лівий клік усе одно відкриває оверлей, тож погоджений дизайн недоторканий. Карта сайту переписана: дати, мовні пари, зображення, оферта й журнал; виключення приховних і тестового товару закріплене тестом.

- **Статті отримують справжні маршрути** `/[locale]/journal/[slug]` (SSG) із того ж `i18n`.
  Мінімальний ризик для погодженого дизайну: картка в блозі стає `<a href>`, оверлей лишається
  перехоплювати клік для людини, краулер іде за посиланням. Плюс `Article` JSON-LD.
- Подарункові набори: без нових маршрутів, але `ItemList` на головній і присутність у `sitemap`
  через якір.
- `sitemap` v2: `lastModified` із ревізії каталогу, `alternates.languages`, `images`, `/offer`,
  маршрути журналу.

### S4 — AI-пошук

**Зроблено:** `robots.ts` називає окремо ботів, що цитують, і тренувальних — обидві групи дозволені (рішення зафіксоване в комментарі з причиною). `/llms.txt` генерується з живого каталогу з ревалідацією раз на годину, тож не може рекламувати фасування, якого вже немає; поза робочим середовищем віддає 404. Головне — **e2e-тест на видимий текст**: читає сире HTML `/ua` і `/en`, як краулер, і вимагає присутності назв, ваг, цін, Нової пошти й контактів. Це захист саме від того, що знайшов ресьорч.

- `robots.txt`: явні групи для ботів, що цитують (`OAI-SearchBot`, `ChatGPT-User`,
  `Claude-SearchBot`, `Claude-User`, `PerplexityBot`, `Perplexity-User`, `Googlebot`,
  `Google-Extended`, `Bingbot`, `Applebot`).
  **Рішення клієнта:** чи дозволяти тренувальні боти (`GPTBot`, `ClaudeBot`, `CCBot`,
  `Meta-ExternalAgent`, `Amazonbot`, `Bytespider`). Моя рекомендація — дозволити: для малого
  бренду присутність у корпусі це плюс, блокування лише зменшує охоплення. Боти тренування й
  пошуку — різні токени, кожен треба називати окремо.
- `llms.txt` — маршрут, що генерується з каталогу з тим самим кеш-тегом: хто ми, товари з вагами
  й цінами текстом, доставка, оплата, контакти, посилання на канонічні сторінки.
- **Тест на видимий текст:** перевірка згенерованого HTML `/ua` і `/en` на наявність фактів, якими
  AI відповідає на «купити ікру в Україні» — назви, ваги, ціни, Нова пошта, способи оплати,
  регіон виробництва, контакти. Це захист від регресії, коли контент поїде в клієнтський оверлей.
  Прихований текст не використовуємо — це клоакінг і ризик санкцій.
- `htmlLimitedBots` не потрібен: вітрина SSG, метадані вже в `<head>` на білді.

### S5 — UTM і аналітика

**Оновлено 14.11:** панель каналів отримала вікно звіту (7 днів / 30 днів / рік) — цілі київські доби, що закінчуються сьогодні, тож звіт, відкритий двічі за день, покриває ті самі дні, а підпис називає точні дати («з 8 по 14 листопада 2026 р. включно»). Перемикач — звичайне посилання `?period=`, тож сторінка перемальовується сервером із кешованої агрегації, без жодного запиту з браузера. Графік — колони в стилі organ pipes, намальовані рідним SVG у токенах адмінки (`src/domain/channel-chart.ts` тримає чисту геометрію, тому її покрито тестами й можна рендерити прев'ю без бази). Під графіком ті самі цифри текстом: канал, кількість, частка, сума, за спаданням, плюс рядок «Разом» і час зрізу даних. `npm run chart:preview` малює панель у `.local/chart-preview/` без бази й сесії.

**Зроблено:** `src/domain/attribution.ts` — first-touch, cookie на 90 днів, закритий перелік каналів із мапуванням платформних написань (`ig`, `chatgpt.com`, `t.me`) на наші назви, щоб один канал не розпався на три. Значення приходить із cookie, яку редагує відвідувач, і потрапляє в документ Firestore і на екран персоналу, тому все, що не наше, відкидається — під тестом. Атрибуція дописується в замовлення й заявки, тобто в записи, які **і так пишуться**: нуль додаткових записів. Канал свідомо **поза** fingerprint замовлення, інакше повтор із іншої лендінг-сторінки виглядав би конфліктом. Дашборд каналів — агрегації `count`+`sum` на джерело під кешем 60 с, доданий індекс. GA4 не підключався: потребує банера згоди, це окреме рішення.

Розділення, яке тримає нас у безкоштовних лімітах:

| Що                               | Чим                                   | Наша інфраструктурна ціна               |
| -------------------------------- | ------------------------------------- | --------------------------------------- |
| Трафік, джерела, регіони, країни | GA4 / Firebase Analytics              | 0 — скрипт у браузері, події безлімітні |
| **Конверсії по каналах**         | поле `attribution` у наших документах | **0 додаткових записів**                |

- UTM ловиться на першому візиті (`utm_*`, `ref`) і кладеться у **first-party cookie** на 90 днів
  (cookie, а не `localStorage`, бо його мусить прочитати сервер; це не контактні й не платіжні дані,
  тому заборона з `docs/engineering-conventions.md` не порушується).
- `attribution: { source, medium, campaign, firstSeenAt }` дописується полем у документ замовлення,
  заявки й видачі промокоду — тобто в запис, який ми **і так пишемо**. Жодного нового запису.
- Дашборд: «Переходи за UTM» стає справжнім. Firestore не має `GROUP BY`, тому ~11 агрегаційних
  `count`/`sum` запитів (по одному на джерело) під `unstable_cache` на 60 с — той самий патерн, що
  вже працює для `completedOrders`. Агрегація білиться як кілька читань, не як вся колекція.
- Це дає замовнику те, що насправді потрібно: «скільки замовлень і на яку суму прийшло з Instagram,
  Google, ChatGPT», а не просто візити.
- **Конструктор посилань** в `/admin/seo/utm`: фіксований перелік джерел (instagram, facebook,
  threads, tiktok, youtube, google, chatgpt, perplexity, gemini, telegram, email), готові посилання
  з кнопкою копіювання. Без модерації — як і просив замовник.
- **Рішення, яке блокує GA4:** GA4 ставить сторонні cookie, тобто потрібен банер згоди, якого в
  проєкті немає. Тому GA4 — окремо й пізніше, разом із банером. Наша атрибуція на замовленнях
  банера не потребує (це власні дані замовлення), тож реліз вона не блокує.

### S6 — Модуль `/admin/seo`

**Зроблено:** вкладка «SEO» — панель технічного стану тільки для читання (індексація, canonical і мови, кількість адрес у карті сайту, структуровані дані, llms.txt) і посилання на SEO товару в його картці, без дублювання редактора. Вкладка «Переходи й UTM» — готові посилання по каналах із кнопкою копіювання й таблиця замовлень за каналами. Модерації robots.txt і llms.txt немає навмисно: вони генеруються з даних.

**Свідоме відхилення від плану:** заголовок і опис головної в адмінку **не** виніс. Вони лежать у `src/i18n`, спільному з рештою вітрини, і редактор для двох рядків потребував би окремого сховища, інвалідації кешу й злиття з файловим фолбеком — непропорційно до вигоди, коли до релізу їх правлять вручну. Якщо потрібно — окрема задача.

Останнім: модерує те, що вже існує.

- `moderation`: заголовок і опис головної на локаль + картка прев'ю «як виглядає посилання в месенджері».
- Посилання на SEO товару в його картці — без дублювання редактора.
- **Технічний стан, тільки читання:** чи є canonical і hreflang, скільки URL у sitemap, стан robots,
  які товари виключені й чому. Найкорисніша частина, і рахується безкоштовно з уже наявних даних.
- `utm`: конструктор посилань.
- `robots.txt` і `llms.txt` модерації не мають — генеруються з даних.

## 5. Рішення: що вирішено і що відкрите

| Рішення                             | Стан                                                                                                                                                                                                          |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Тренувальні AI-боти                 | **Дозволені всі** — реалізовано за моєю рекомендацією, без окремого підтвердження клієнта. Причина записана в комментарі `src/app/robots.ts`; відкотити — один список.                                        |
| GA4 і банер згоди                   | **Відкрите.** Не підключався: потребує банера, якого в проєкті немає. Наша атрибуція на замовленнях банера не потребує і реліз не блокує. Сюди ж — заготовки «Відвідування», «Регіони», «Країни» на дашборді. |
| Окремі сторінки наборів             | **Не робимо** — `ItemList` на головній, нульовий ризик для погодженого дизайну.                                                                                                                               |
| Текст і картинка прев'ю             | **Мій варіант у коді.** Клієнт може замінити до релізу: `npm run social:build` після зміни майстра або підпису.                                                                                               |
| Заголовок і опис головної в адмінці | **Відхилено свідомо.** Лежать у `src/i18n`, спільному з вітриною; редактор для двох рядків потребував би окремого сховища, інвалідації кешу й злиття з файловим фолбеком. Окрема задача, якщо знадобиться.    |

## 6. Що лишилося

1. **Перевірка розширених результатів** Google на зібраному проді (Rich Results Test) — після
